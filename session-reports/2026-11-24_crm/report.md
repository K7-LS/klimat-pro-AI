# Карточка объекта, файлы и отчёт по оплатам

Проверено 24 ноября 2026 года. Это версия для локальной приёмки. Рабочий nginx на ПК отдаёт сборку `index-BJJ_MVWa.js`.

## Результат

После создания открывается карточка объекта. Вкладки задач, переписки и файлов загружают свои данные при открытии. В списке задач выбранный объект передаётся новой задаче. История комментариев к проекту и отдельный диалог с заказчиком доступны из одной вкладки. Прежние личные задачи остаются личными, пока сотрудник сам не укажет объект.

В разделе файлов используется действующий Nextcloud. Браузер сохраняет ответ как двоичные данные для всех расширений. Лимиты формы составляют 20 МБ на вложение и 100 МБ на объект. Для файлов проекта применяется одно правило выдачи. Владелец и администратор имеют доступ ко всем материалам объекта. Сотруднику требуется членство в доступном ему командном объекте или проекте маркетплейса. Обзор предложений сам по себе доступа к вложениям не даёт. Заказчик получает только явно отмеченные файлы своего объекта. Снятие отметки закрывает последующее скачивание. Прежние экземпляры, уже сохранённые получателем, остаются у него.

В отчёте владелец видит остаток стоимости своей работы после распределения долей. Исполнитель видит сумму долей, назначенных его учётной записи. Оплата рассчитывается пропорционально фактическим поступлениям по договору. Сведения о переводе исполнителю CRM отдельно не подтверждает. Суммы в рублях округляются до копеек. Доступны фильтр стадий, выбор нескольких объектов и печать. [Учебный пример на A4](<Пример отчёта по оплатам.pdf>).

## Порядок выпуска

По отдельному разрешению владельца сохранить действующие определения файловых политик и функций, текущие Edge и фронтенд. Применить `supabase/migrations/20261124_0001_project_file_access.sql`, затем развернуть функцию `nextcloud` и фронтенд со штатным production-конфигом. Учебная сборка содержит адрес стенда. Проверить действия на двух согласованных аккаунтах, выдачу и отзыв тестового файла, печать по известному объекту и идентификатор сборки в nginx и снаружи. Если новый интерфейс потребует отката, вернуть прежний фронтенд. Суженные серверные права сохранять при разборе сбоя.

При смене стадии на «Оплачен» форма может добавить платёж на остаток договора сегодняшней датой. Пересмотр правила и сверка старых записей требуют решения владельца. Реальные суммы и существующие вложения в этой работе не менялись.
